# Automatic source positions in report assets

The normal asset pipeline now requests missing Match Room positions from the original video and all original user selections. It does not pass action conclusions, manually reviewed coordinates, expected directions or prior inferred identities to the position model. Canonical action findings and report prose remain unchanged.

Each clip has one bounded source window. All original reference images are decoded once and shared across requests. Two owned model workers share a 420-second wall budget; source/selection/event binding and freshly rebuilt payload hashes protect exact receipt replay. Per-event receipts are checkpointed before video encoding. Access failures stop further requests; unavailable or uncertain observations suppress graphics.

Player ellipses require independently localized endpoints to resolve uniquely to measured person contours. Forward and backward paths must agree; missing feet, identity conflicts and unknown rows break the path. Explicit source-position results never fall back to approximate sparse ellipses in the frontend. A measured active ball may continue after its identified player leaves the image, but uncertain identity clears that permission. Arrows require observed post-contact endpoints and camera compensation. Explicit position arrows do not fade beyond their last observed source frame.

These mechanisms are integrated on the draft branch; visual acceptance remains a separate requirement. The first all-ten-tap integration request produced positions; a no-new-model-call local replay produced one eight-frame ellipse segment and two short ball-direction segments. Actual React/Chromium playback verified these short intervals and suppression in the uncertain interval. A further run checks all eight report clips using the retained action analysis and writer output. This is presentation regeneration, not a fresh full source-analysis run or authenticated upload test. Keep draft pending the complete result.
